# Internationalisation (i18n)

Chativa uses [i18next](https://www.i18next.com/). The widget ships with **English (`en`)** and **Turkish (`tr`)**. Anything else you add at runtime.

## Set the active language

```ts
import { i18next } from "@chativa/ui";   // re-exported from @chativa/core
i18next.changeLanguage("tr");
```

Or declaratively, before mount:

```js
window.chativaSettings = { locale: "tr" };
```

All `LitElement` components that extend `I18nMixin` (every Chativa component does) re-render automatically when the language changes.

## Add a new language

```ts
import { i18next } from "@chativa/ui";

i18next.addResourceBundle("de", "translation", {
  header:    { title: "Chat", subtitle: "Wir sind hier" },
  input:     { placeholder: "Nachricht schreiben..." },
  commands:  { clear: { description: "Verlauf löschen" } },
});

i18next.changeLanguage("de");
```

## Right-to-left languages

Chativa mirrors its layout for right-to-left languages. Switching to Arabic, Hebrew, Persian or Urdu flips the whole widget: bot messages sit on the right and user messages on the left, the send button moves to the left of the composer, and the back arrow, send icon and carousel chevrons point the other way.

### How the direction is chosen

`<chat-iva>`, `<chat-bot-button>` and `<agent-panel>` each carry a `dir` attribute that follows the active i18next language:

```ts
import { i18next } from "@chativa/ui";

await i18next.changeLanguage("ar");   // <chat-iva dir="rtl">
await i18next.changeLanguage("en");   // <chat-iva dir="ltr">
```

Every shadow root inherits that direction, so you don't need to configure anything per component.

Only the base language subtag is compared, so `ar-EG`, `he-IL` and `fa_IR` count as RTL too. The list and the helpers are exported:

```ts
import { RTL_LANGUAGES, isRtlLanguage, getLanguageDirection } from "@chativa/ui";

RTL_LANGUAGES;                  // ["ar", "he", "fa", "ur"]
isRtlLanguage("ar-EG");         // true
getLanguageDirection("tr");     // "ltr"
```

The widget only handles layout direction. You still have to load the translations yourself (see [Add a new language](#add-a-new-language)). Without them, Arabic is laid out RTL but shows the English fallback strings.

### Forcing a direction

A `dir` you set yourself always wins over the language:

```html
<!-- Always RTL, whatever language is active -->
<chat-iva dir="rtl"></chat-iva>
```

This works in markup, with `el.dir = "rtl"` and with `el.setAttribute("dir", …)`, whether you set it before or after the widget mounts. Once you set `dir`, Chativa leaves it alone, even when your value matches what the language would have chosen. If you remove the attribute, the direction follows the language again. Set `dir` on each root you mount, for example both `<chat-iva>` and `<chat-bot-button>`.

### What mirrors and what doesn't

| Mirrors under RTL | Stays as-is |
|---|---|
| Message alignment, avatars, bubble "tail" corners | Rating stars: 1 → max still reads left-to-right (the usual convention); labels and buttons around them still mirror |
| Composer order (attach · emoji · text · send) | Bar charts keep their x-axis order, matching the SVG line chart |
| Emoji picker, slash-command popup, typing bubble | Code blocks (`pre`) are always LTR |
| Feedback buttons and tool-call trace offsets | The launcher corner and the popup / side-panel edge (see [Theming → Position and RTL](./theming.md#position-and-rtl)) |
| Conversation-list slide-in, image-gallery arrows and arrow keys | |

### Mixed-direction text

Message bubbles use `dir="auto"`, so each message gets its base direction from its first strong character. An English reply inside an Arabic UI keeps its punctuation in the right place, and the bubble still sits on the correct side. Links and inline code inside messages are bidi-isolated (`unicode-bidi: isolate`), and timestamps are wrapped in `<bdi>`, so URLs, numbers and times don't reorder the sentence around them. The composer input also uses `dir="auto"`.

### Custom components

Built-in components use only **CSS logical properties**. Custom message types and custom GenUI components are your responsibility, so write them the same way:

| Instead of | Use |
|---|---|
| `margin-left` / `margin-right` | `margin-inline-start` / `margin-inline-end` |
| `padding-left` / `padding-right` | `padding-inline-start` / `padding-inline-end` |
| `left: 0` / `right: 0` | `inset-inline-start: 0` / `inset-inline-end: 0` |
| `text-align: left` | `text-align: start` |
| `border-left` | `border-inline-start` |
| `border-top-left-radius` | `border-start-start-radius` |

For anything logical properties can't express, such as flipping an arrow icon or the sign of a `translateX()`, use the `:dir()` selector from inside your shadow root:

```css
:host(:dir(rtl)) .arrow { transform: scaleX(-1); }
```

`:dir()` follows the inherited direction, so it works however deep the component is nested. An attribute selector like `[dir="rtl"]` only matches the element that carries the attribute.


## Override built-in strings

You can override any key in any language. Two formats are supported via `chativaSettings.i18n`:

### Per-language

```ts
window.chativaSettings = {
  i18n: {
    all: { header: { title: "Customer Care" } },     // applied to every language
    tr:  { header: { subtitle: "7/24 buradayız" } }, // tr-only override
  },
};
```

### Flat (applies to every registered language)

```ts
window.chativaSettings = {
  i18n: { header: { title: "Customer Care" } },
};
```

`applyGlobalSettings()` re-applies your overrides on `languageChanged`, so they survive runtime locale switches.

## In your own components

Extend `I18nMixin` and use the reactive `t()` method:

```ts
import { LitElement, html } from "lit";
import { I18nMixin } from "@chativa/core";

class HelpButton extends I18nMixin(LitElement) {
  render() {
    return html`<button>${this.t("commands.help.label")}</button>`;
  }
}
```

Or in slash commands / GenUI components — pass the **lazy** form so translations are read at execute time, not registration time:

```ts
registerCommand({
  name: "help",
  description: () => t("commands.help.description"),  // function → resolved later
  usage:       () => t("commands.help.usage"),
  execute({ args }) { /* ... */ },
});
```

See [`domain/ports/ISlashCommand.ts`](https://github.com/AimTune/chativa/blob/main/packages/core/src/domain/ports/ISlashCommand.ts) → `resolveText()`.
